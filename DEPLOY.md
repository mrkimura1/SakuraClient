# Деплой сайта и API на Vercel

Сайт `https://sakuraclient-nvp2.vercel.app/` теперь полностью работает на Vercel:
статические страницы + serverless API (`/api/*`) + Postgres. Локальный сервер
(`start-server.bat`) больше не нужен.

## Что уже сделано

- `api/index.js` — весь API (регистрация, вход, личный кабинет, активация
  ключей, магазин, заказы, админка) в одном serverless-обработчике.
- `lib/*` — работа с Postgres, паролями (PBKDF2, совместимо со старой базой),
  JWT и DTO.
- `assets/api.js` — запросы идут на тот же домен, где открыт сайт. Ошибки
  `LOCAL_API is not defined` больше нет.
- При первом запросе API сам создаёт таблицы и заполняет товары.
- `admin.html` — админ-панель на сайте (`/admin.html`): пользователи (роли,
  сброс HWID), ключи (создание и удаление), скидки, заказы. Работает поверх тех
  же `/api/admin/*`, что и старая вкладка «Админ-панель» в лоадере, поэтому новой
  серверной части не требует. Ссылка «Админка» в шапке кабинета появляется только
  у Owner; остальные видят «Нет доступа». Роль Owner через панель не выдаётся —
  это запрещено API (владелец в базе может быть только один).
- В лоадере больше нет ни админки, ни магазина: там остались вход, активация
  ключа, профиль и запуск клиента. Покупка тарифа — только на сайте
  (`/app.html` → «Магазин» → FunPay → ключ → активировать в лоадере).
- `download/SakuraLoader.exe` — лоадер. При первом запуске он скачивает ВСЁ с
  этого же домена: `download/SakuraClient-26.2.jar` и зеркало Minecraft
  `download/mc/26.2/**` (манифест, профиль, клиент jar, Fabric Loader,
  библиотеки, ресурсы, Java 25) в `C:\SakuraClient`. Mojang, FabricMC и
  Adoptium лоадер не трогает — адреса подменяются в `Game/Mirror.cs`.
- Вложенные моды клиента (Fabric API, ViaFabricPlus, modmenu, IAS) лежат в
  `download/mc/26.2/mods/`: в jar клиента их нет, только объявление в
  `fabric.mod.json`. Лоадер сам читает это объявление и докладывает недостающие
  jar в `C:\SakuraClient\game\mods`, откуда их подхватывает Fabric Loader.
  Без этого клиент падает с `requires any version of fabric-api, which is missing!`.

## Что нужно сделать один раз (2 минуты)

> Активный домен — `https://sakuraclient-nvp2.vercel.app/`. Лоадер скачивается
> с него же, поэтому сайт, API и лоадер работают с одной базой.
> Старый `sakuracleent.vercel.app` не используется: на нём `/api/status`
> отдаёт `"database": "missing"`.

1. Залей папку `wwwroot` на Vercel (push в `SakuraClient.git` или `vercel deploy`)
   и открой в [Vercel Dashboard](https://vercel.com/dashboard) этот проект.
   Адрес проекта — `https://sakuraclient-nvp2.vercel.app`.
2. Перейди в **Storage → Create Database → Postgres** (Neon).
3. Нажми **Connect Project** и выбери этот проект. Vercel сам добавит
   переменные окружения (`DATABASE_URL` и/или `POSTGRES_URL`).
4. (Рекомендуется) В **Settings → Environment Variables** добавь:
   - `JWT_SECRET` — любая длинная случайная строка (например, 64 символа).
   - `OWNER_USERNAME` — логин владельца, например `Sakura`.
   - `OWNER_PASSWORD` — пароль владельца (минимум 6 символов).
   После первого успешного запроса владелец создастся автоматически.
5. Собери и обнови `download/SakuraLoader.exe` в этой же папке (см. ниже) —
   иначе лоадер останется ходить на старый домен.
6. Сделай **Redeploy** (Deployments → ⋯ → Redeploy) или просто запушь коммит.

## Проверка

1. Открой `https://sakuraclient-nvp2.vercel.app/api/status` — должно быть:
   ```json
   { "name": "SakuraClient API", "version": "26.2", "status": "online", "database": "ok" }
   ```
2. Открой сайт → **Регистрация** → создай аккаунт.
3. Войди → в личном кабинете появится профиль, подписка и магазин.
4. Активируй ключ в блоке «Активация ключа».
5. Нажми «Скачать лоадер» и запусти `SakuraLoader.exe`. При первом запуске
   он скачает клиент, Minecraft, библиотеки, ресурсы, моды клиента и Java в
   `C:\SakuraClient`; дальше — только запускает клиент, ничего не ища и не
   перекачивая. Если клиент закрылся сам через секунду — смотри
   `C:\SakuraClient\logs\client-*.log`: там почти нет других причин — не хватает
   файла из `download/mc/26.2/mods/` (404 на сайте) либо самого зеркала.

## Переменные окружения

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `DATABASE_URL` (или `POSTGRES_URL`) | Да | Строка подключения к Postgres. На Vercel подставляется автоматически. |
| `JWT_SECRET` | Нет | Ключ подписи токенов. Если не задан, выводится из `DATABASE_URL`. |
| `OWNER_USERNAME` | Нет | Логин владельца для одноразового бутстрапа. |
| `OWNER_PASSWORD` | Нет | Пароль владельца (если аккаунта ещё нет). |
| `OWNER_KEY` | Нет | Значение owner-ключа. Если не задан — ключ генерируется сам и печатается в лог функции. |

## Ключ «навсегда + Owner»

Один ключ, который при активации даёт подписку навсегда и роль владельца.
Товар для него не создаётся: ключ привязан к существующему «Навсегда», а
права включает флаг `license_keys.grants_owner`
([db.js:ensureOwnerKey](lib/db.js), [api/index.js:activateKey](api/index.js)).

Как получить:

1. (По желанию) В Vercel задай `OWNER_KEY` — своё значение, например
   `SAKURA-XXXX-XXXX-XXXX`. Не задашь — API сгенерирует ключ сам и напишет
   `[sakura] Owner-ключ готов к активации: SAKURA-…` в
   **Deployments → ⋯ → View Function Logs**.
2. Redeploy, затем любой запрос к API (например открой `/api/status`) — ключ
   создаётся один раз и больше не меняется.
3. Войди на сайт нужным аккаунтом → «Активация ключа» → введи ключ. Ответ:
   «Навсегда и права владельца».
4. Ключ одноразовый: вторая активация даст «Этот ключ уже активирован». Если
   владелец в базе уже есть — «Владелец уже назначен на <логин>» (в схеме стоит
   частичный уникальный индекс `users_single_owner`, второй Owner невозможен).

Не держи значение в открытом репозитории: `wwwroot` публичный, поэтому ключ либо
в переменной окружения, либо сгенерирован при деплое.

## Выдать Owner существующему аккаунту

Владельцем может быть только один аккаунт (в схеме есть частичный уникальный
индекс `users_single_owner`). Чтобы поднять права уже зарегистрированному
логину:

1. В Vercel: **Settings → Environment Variables** → `OWNER_USERNAME` = `Sakura`.
   `OWNER_PASSWORD` не нужен — аккаунт существует, `ensureOwner()` сделает
   `UPDATE users SET role = 'Owner'`.
2. **Redeploy**. При первом запросе к API владелец получит права, и на сайте в
   кабинете появится ссылка «Админка» (`/admin.html`).
3. Проверить: войти под Sakura → `/app.html` → админка; переменную после этого
   можно удалить, повторных повышений не будет.

## Цены

Цены задаёт `SEED_PRODUCTS` в `lib/db.js` (299 ₽ / 399 ₽ / 499 ₽ / 149 ₽):
`ensureSchema()` при каждом холодном старте синхронизирует их с таблицей
`products`, поэтому смена цифры в этом массиве + Redeploy меняет цены на сайте.
Редактора товаров в админке нет.
`Seed.cs` локального .NET-сервера держит те же цифры.
Статические карточки в `index.html` — только fallback: при загрузке страницы
`pricingGrid` перерисовывается с `/api/products`.
Ссылки «Купить» ведут на лоты FunPay с фиксированной ценой — их нужно
переставить вручную, иначе сайт покажет одну цену, а оплата будет по другой.

## Локальный запуск API (необязательно)

```bash
npm install
# .env с DATABASE_URL=...
npx vercel dev
```

## Важно

- Аккаунты из локального `sakura.db` не переносятся автоматически: база на
  Vercel новая. Зарегистрируй аккаунты заново (хеши паролей совместимы, при
  желании данные можно импортировать через `psql`).
- Лоадер `SakuraLoader.exe` по умолчанию ходит на
  `https://sakuraclient-nvp2.vercel.app/` — тот же домен, что и сайт.
  Переопределить адрес можно переменной окружения `SAKURA_API`.
- Если Vercel начнёт редиректить один домен на другой (сейчас
  `sakuraclient-nvp2.vercel.app` отвечает `307` на
  `sakuraclient-client.vercel.app`), сайт и лоадер продолжают работать:
  `.NET` при редиректе на другой хост снимает заголовок `Authorization`,
  поэтому лоадер сам проходит редиректы и возвращает токен на каждом шаге
  (`src/SakuraLoader.Client/Api/Api.cs`). Если это убрать — все защищённые
  запросы (активация ключа, заказы, `/api/me`) начнут отдавать
  «Требуется авторизация».
- Старый домен `sakuracleent.vercel.app` больше не используется: на нём база не
  подключена (`/api/status` отдаёт `"database": "missing"`).
- Локальный сервер (`server/`) больше не нужен для работы сайта и лоадера.
- Зеркало `download/mc/26.2/**` — часть сайта: без него лоадер не может ни
  скачать, ни запустить клиент. Если оно пропало (404 на
  `/download/mc/26.2/mojang/mc/game/version_manifest_v2.json`), значит `wwwroot`
  залит без него или Vercel обрезал коммит по лимиту 100 МБ на файл.

## Зеркало Minecraft (`download/mc/26.2`)

Файлы для зеркала собирает `tools/mirror-mc.ps1` (в корне проекта, вне `wwwroot`)
или `tools/mirror-mc.bat` — двойной клик. Путь по умолчанию уже указывает на
`wwwroot\download\mc\<версия>`, отдельно передавать его не нужно:

```bat
tools\mirror-mc.bat
```

Скрипт идемпотентен: уже скачанные файлы пропускает, докачивает новые.
Кладёт в `download/mc/26.2/`: `packages/` (.sha1/.jar по хешам), `mojang/`
(манифест версий и профиль), `libraries/` (только Windows-нативы), `fabric-meta/`,
`maven/`, `assets/objects/` + `assets/hosted.txt`, `mods/`, `java/`.
Всего ~230 МБ, каждый файл меньше 100 МБ, поэтому Vercel/GitHub его держат.

Что сознательно НЕ качается:

- звуки и `lang` из `extra` (~446 МБ) — не влезают в лимит 100 МБ на файл и в
  разумный размер репозитория. Игра будет без звуков; `assets/hosted.txt`
  говорит лоадеру, какие объекты реально лежат на сайте, чтобы он не запрашивал
  5000 файлов и не получал 404.
- `server.jar`, `.xml`-дескрипторы и linux/macos-нативы (`Test-SkipArtifact`).

`$ClientMods` в начале скрипта — список модов, которые лоадер должен забрать с
сайта. Он сверяется с `fabric.mod.json` клиента по имени файла: обновишь клиент
со своими вложенными модами — обнови и этот список (артефакты берутся с
maven.fabricmc.net и Modrinth), иначе мод резолвера Fabric не найдёт.

Проверить зеркало без деплоя:

```bash
curl -I https://sakuraclient-nvp2.vercel.app/download/mc/26.2/mods/fabric-api-0.156.0%2B26.2.jar
```

`+` в имени Fabric API в URL обязан быть как `%2B`.

## Обновление файлов для скачивания

После сборки в `SakuraLoader\dist\SakuraClient26.2` (или после `publish.bat`):

```bat
copy /y "dist\SakuraClient26.2\SakuraLoader.exe" "src\SakuraLoader.Server\wwwroot\download\SakuraLoader.exe"
copy /y "dist\SakuraClient26.2\client\SakuraClient-26.2.jar" "src\SakuraLoader.Server\wwwroot\download\SakuraClient-26.2.jar"
```

Если менялся клиент (новые версии вложенных модов) — пересобери зеркало командой
из раздела про `download/mc/26.2`, он докачает только недостающие файлы.

Затем закоммить и запушь папку `wwwroot` — Vercel пересоберёт сайт.
Проверь, что зеркала не отрезали: `/api/status` → `database: ok`,
`/download/SakuraClient-26.2.jar` → 200, `/download/mc/26.2/assets/hosted.txt` → 200.
